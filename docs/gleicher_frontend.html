Core deliverables

What to include

  • Original project proposal (if available).
  • Source code with build/run notes; ideally a GitHub repo (uwgraphics if applicable).
  • Example results: demo link, videos, images, or use-case descriptions.
  • Bibliography with full citations; annotated is preferred (what you learned from each).
  • Final project document (see required sections below).

Final document

The four required sections

1) Describe your results

What you built, methods, how it works, how it is used, limitations, and how you evaluated it. Include enough documentation for someone else to run and extend it.

What it does Methods Limitations

2) Describe the work

How you got there: where time went, what you tried, what was hard or easy, and what did not make the final cut. Use your status reports to jog memory.

Process Attempts Dead ends

3) What you learned

Technical and non-technical takeaways. Focus on learning outcomes, not only the artifact.

Lessons Skills Insights

4) Self-evaluation

How happy you are with the project, what you would do differently, and guidance for the next person (possibly future you).

Submission checklist

Code, docs, and handoff

  • Code present with build/use instructions; verify all files are present.
  • Repo accessible (uwgraphics fork/ownership if required).
  • Large assets (videos, data) stored appropriately; document locations.
  • Each directory has a brief README for orientation.
  • Results artifacts linked (demos, images, videos, use cases).
  • Bibliography complete and preferably annotated.
Reflection prompts

Use in weekly status notes

Plan vs outcome
State your goals for the week and what you accomplished; call out gaps and why.
Debug the process
Note blockers (alignment issues, data quality, interaction bugs) and how you resolved or mitigated them.
Evaluate the work
How do the results support analysis? Are selections stable, clusters coherent, metrics reliable?
Next steps
List immediate next goals and how they connect to the bigger picture.
